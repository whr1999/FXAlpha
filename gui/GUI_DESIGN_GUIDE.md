# FXAlpha GUI Design Guide

## 1. 目标与适用范围

本规范用于指导 FXAlpha 后续 GUI 页面建设，沉淀当前平台的统一视觉标准与工程复用规则。

- 视觉锚点：`http://localhost:18081/gui` 当前「因子研究」界面
- 规范定位：统一基座 + 模块可变强调
- 本文档不引入新的 HTTP API、前端状态结构或数据契约
- 本文档优先约束新页面与后续改版页面；已有页面可按“现状兼容”逐步收敛

设计目标：

- 保持平台感和专业感，避免通用后台模板观感
- 保持红蓝双强调的 FXAlpha 识别度；深色为默认主题，浅色为等价可选主题
- 保持组件、标题层级、圆角、阴影、表单和状态表达的一致性
- 让产品、设计、前端工程师可以基于同一份文档直接落地

## 2. 设计原则

### 2.1 统一基座

所有模块默认复用同一套背景、字体、圆角、阴影、边框透明度和信息层级。模块之间不得各自发明新的基础设计语言。

### 2.2 模块可变强调

允许不同模块在不破坏基础风格的前提下，调整局部渐变方向、局部强调层和少量 accent 卡片样式。但不允许改动：

- 主背景逻辑
- 主文字体系
- 标题层级
- 圆角体系
- 默认卡片形态

### 2.3 信息优先级先靠层级，不先靠颜色

高优先级信息优先用以下方式突出：

1. 更高字重
2. 更高亮度
3. 胶囊式状态块或卡片分组
4. 卡片位置和布局顺序

只有在确实需要表达语义时才使用绿色、橙色、红色等状态色。

### 2.4 GUI 保持薄层

GUI 负责：

- 展示状态
- 承载操作入口
- 清晰组织运行时信息

GUI 不应复制后端业务逻辑，不应把业务判断埋进样式或页面结构。

## 3. 视觉基座与主题 Tokens

以下 token 已在 [styles.css](styles.css) 的 `:root` 中存在，应视为平台基础设计 token。

### 3.1 颜色 Tokens

| Token | 当前值 | 角色 | 使用规则 |
| --- | --- | --- | --- |
| `--bg` | `#070b14` | 主背景基底 | 作为整页深色背景起点，不单独作为卡片底色 |
| `--rail` | `#050812` | 侧栏/深层底 | 用于 rail 深层背景和暗部基底 |
| `--panel` | `rgba(15, 23, 42, 0.84)` | 玻璃卡片底 | 主内容卡片、Hero、工作区容器默认底色 |
| `--panel-solid` | `#101827` | 实心输入底 | 表单输入、代码块深色实体底 |
| `--ink` | `#eef6ff` | 主文字 | 一级标题、正文关键值、按钮主文字 |
| `--muted` | `#93a7bf` | 次级文字 | 说明文、字段标签、次级提示、表头辅助文字 |
| `--line` | `rgba(148, 163, 184, 0.18)` | 标准边线 | 通用边框、细分割线、浅层容器边界 |
| `--accent` | `#c81d25` | 主强调红 | 品牌热区、渐变一端、红色强调卡片 |
| `--accent-2` | `#2563eb` | 主强调蓝 | 主交互、主渐变、激活态、悬停态 |
| `--accent-3` | `#1d4ed8` | 深蓝补强 | 更稳重的辅助蓝层，少量用于增强层次 |
| `--good` | `#047857` | 成功色 | 在线、成功、通过状态 |
| `--warn` | `#c2410c` | 警示色 | `inline-warning`、提醒、待确认风险 |
| `--danger` | `#b91c1c` | 危险色 | 删除、不可逆操作、严重失败状态 |

补充规则：

- 页面背景应保持“深底 + 红蓝双径向光斑 + 纵向渐变”的结构，不改成纯平面纯黑。
- 新模块如需强调色变化，优先保持 `--accent` 和 `--accent-2` 不变，只在局部 `accent-* card` 中调整透明度和渐变分布。
- 不允许新增高饱和紫色作为主视觉，以免偏离当前 FXAlpha 识别。

### 3.2 深浅主题契约

- `html[data-theme="dark"]` 是默认深色主题；`html[data-theme="light"]` 是同一组件体系的浅色映射。
- 主题切换只允许改变视觉 token、表面、边框、文字与装饰色，不得改变业务状态、DOM 数据契约、权限或操作流程。
- 用户选择保存在浏览器本地；首次访问可跟随系统偏好，脚本不可用时回退到深色主题。
- 浅色主题使用冷白灰背景与红蓝低透明光斑，保留玻璃层次，不使用大面积刺眼纯白。
- 成功、警示、危险等语义色在两套主题中语义必须一致，并分别满足可读性。
- 新组件必须使用 `--ink`、`--muted`、`--panel`、`--line` 等语义 token，避免硬编码仅在深色背景可读的颜色。

### 3.3 字体 Tokens

| Token | 当前值 | 角色 | 使用规则 |
| --- | --- | --- | --- |
| `--font-display` | `Aptos Display`, `Segoe UI Variable Display`, `PingFang SC`, `Microsoft YaHei`, `sans-serif` | 大标题/模块标题 | Hero、品牌名、二级标题 |
| `--font-body` | `Aptos`, `Segoe UI Variable Text`, `PingFang SC`, `Microsoft YaHei`, `sans-serif` | 正文/UI 文本 | 正文、按钮、字段、表格 |
| `--font-mono` | `JetBrains Mono`, `Cascadia Code`, `Consolas`, `monospace` | 代码/数据表达 | 表达式、路径、日志片段、结构化数据 |

规则：

- 中文界面优先使用 `--font-body` 和 `--font-display`，不要回退成无风格系统默认字体。
- 所有代码、路径、表达式、模型/因子公式必须使用 `--font-mono`。

### 3.4 圆角与阴影 Tokens

| Token | 当前值 | 角色 | 使用规则 |
| --- | --- | --- | --- |
| `--radius-xl` | `28px` | 大卡片 / Hero | 主 Hero、主要 surface、品牌容器 |
| `--radius-lg` | `20px` | 标准内容卡 | `surface`、中等信息模块 |
| `--radius-md` | `16px` | 中型按钮/容器 | 次级卡片、局部操作块 |
| `--radius-sm` | `12px` | 小组件/提示条 | 小 badge、warning、细粒度盒子 |
| `--shadow` | `0 24px 70px rgba(0, 0, 0, 0.42)` | 主投影 | Hero、surface、workspace 容器、重点卡片 |

规则：

- 不允许新页面随意出现 `4px`、`6px` 这类尖锐圆角。
- 默认优先使用大圆角，维持“胶囊 + 玻璃卡片”的温和科技感。

## 4. 排版层级

以下层级以当前 live GUI 和 `styles.css` 中的实现为基准。

### 4.1 标题层级

| 语义层级 | 当前实现锚点 | 推荐规格 | 用途 |
| --- | --- | --- | --- |
| 品牌标题 | `.brand h1` | `24px`, `700`, `var(--font-display)` | 侧栏品牌名，如 `FXAlpha` |
| 页面一级标题 | `#panel-research .hero h2` | `28px`, `850`, `line-height: 1.18`, `var(--font-display)` | 模块首页核心标题 |
| 全局 Hero 兼容值 | `.hero h2` | `36px`, `var(--font-display)` | 现状兼容，历史页面可保留；新页面优先用模块级覆盖 |
| 模块二级标题 | `.section-head h3` | `24px`, 高字重, `var(--font-display)` | 主卡片标题、工作区模块标题 |
| 卡片三级标题 | 参考 `bi-card` / card head | `18px` 到 `20px`, `700+` | 子模块、统计卡、细分区块标题 |

规则：

- 新页面一级标题默认参照因子研究页，不再默认使用通用 `36px` Hero 标题。
- 一个页面只允许一个最强标题；其他标题通过字重和分组层次递减。

### 4.2 辅助标题与标签

| 语义层级 | 当前实现锚点 | 推荐规格 | 用途 |
| --- | --- | --- | --- |
| Eyebrow / 标签眉题 | `.eyebrow` / `#panel-research .section-head .eyebrow` | `11px` 到 `12px`, `800`, `letter-spacing: 0.16em`, `uppercase`, `color: var(--muted)` | 英文眉题、分类标签、模块前缀 |
| 字段标签 | `.field span` | `13px`, `400`, `color: var(--muted)` | 表单 label、字段名 |
| 指标标签 | `.metric-label` | `12px`, uppercase, `letter-spacing: 0.12em`, `color: var(--muted)` | KPI 名称、信息条标签 |
| 次级说明文 | `.hero-copy`, `.metric-note`, `.rail-note` | `12px` 到 `15px`, `color: var(--muted)` | 解释性说明、操作提示 |

### 4.3 正文与数据表达

| 语义层级 | 推荐规格 | 用途 |
| --- | --- | --- |
| 主正文 | `15px` 到 `16px`, `400` 到 `500`, `color: var(--ink)` | 卡片说明、主叙述内容 |
| 次级正文 | `12px` 到 `13px`, `color: var(--muted)` | 解释说明、非主路径信息 |
| 关键数值 | `20px` 到 `28px`, `700+`, `color: var(--ink)` | KPI 值、重要结果、状态数字 |
| 代码/表达式 | `var(--font-mono)`, 浅蓝文字 + 深色块底 | 因子表达式、路径、日志、代码片段 |

规则：

- 任何“突出内容”优先提升字重和亮度，不用纯色大面积底块抢视觉。
- 表格和数据密集场景中，文字尺寸优先维持 `12px` 到 `13px`，不要为追求“设计感”牺牲信息密度。

## 5. 布局规则

### 5.1 页面骨架

当前标准骨架：

- `.shell`: `213px` 左 rail + 右侧主内容区
- `.rail`: 平台模块导航与全局状态
- `.main`: 主内容区，默认 `padding: 26px`
- `.panel`: 模块面板，按激活状态切换显示

规则：

- 新模块页默认复用 rail + main 的两栏结构。
- 主内容区不能贴边；桌面端保持明确内边距和卡片间距。

### 5.2 Hero 头区

Hero 是模块首页的第一层信息容器，当前由 `.hero` 承担。

推荐结构：

1. 左侧：eyebrow + 页面一级标题 + 可选说明
2. 右侧：1 到 2 个核心动作按钮

规则：

- Hero 必须是玻璃卡片形态，不应退化为纯文字标题行。
- Hero 动作按钮不超过 2 个；更多动作下沉到卡片内或工具条内。

### 5.3 Workspace 导航

当前因子研究页的工作区导航是标准子导航样式：

- 容器：`.workspace-nav`
- 项：`.workspace-tab`
- 激活态：深底 + 蓝色渐变 + 999px 胶囊圆角

规则：

- 模块内部多分区切换优先使用 workspace pills，不再发明新的 tab 组件。
- 子导航应支持横向滚动，优先保证窄屏可用而不是强行压缩文字。

### 5.4 卡片容器

标准主卡片使用 `.surface`，指标卡使用 `.metric-card`。

通用规则：

- 使用当前主题对应的玻璃表面
- 维持高圆角
- 维持统一阴影
- 通过 `gap` 和卡片分组建立层级，不通过密集边线堆层次

## 6. 组件规范

以下组件默认视为平台级标准组件。

### 6.1 侧栏导航 `nav-item`

当前特征：

- `12px` 到 `14px` 级文字
- 深色半透明底
- 激活/悬停时使用红蓝渐变
- 激活态只增强，不翻转到浅底

使用规则：

- 用于一级模块导航
- 一次只允许一个激活项
- 文案采用“主标题 + 简短说明”结构

禁止做法：

- 把一级导航做成纯图标
- 在一级导航里混入强语义状态色

### 6.2 工作区胶囊 `workspace-tab`

当前特征：

- `38px` 左右最小高度
- `999px` 圆角
- 激活态蓝色渐变增强
- 窄屏下支持横向滚动

使用规则：

- 用于模块内部切换和页面内跳转
- 标签文字保持短句，避免两行堆叠

禁止做法：

- 改成传统矩形浏览器 tab 视觉
- 在同一条胶囊导航中混用多套颜色语义

### 6.3 主内容卡 `surface`

当前特征：

- `padding: 20px`
- `border-radius: var(--radius-xl)` 或接近大圆角
- 当前主题对应的玻璃底 + 柔和阴影

使用规则：

- 主功能块、工作台、结果面板、日志块统一使用该形态

禁止做法：

- 绕过主题 token 新建仅适用于单一主题的卡片
- 卡片内部再套多层相似大卡，导致信息层级混乱

### 6.4 指标卡 `metric-card`

当前特征：

- label 使用小号 uppercase
- value 使用大号高亮数字
- note 使用 muted 次级说明

使用规则：

- 用于 KPI、摘要统计、状态摘要
- 1 组卡片内文字结构必须一致

禁止做法：

- 指标卡里塞入长段文本
- 每张指标卡单独发明不同标题尺寸

### 6.5 状态胶囊 `status-chip`

当前特征：

- 胶囊形态
- 左侧小圆点表达状态
- 在线态绿色发光

使用规则：

- 用于 API 在线状态、运行状态、服务状态
- 一行只表达一个主状态，不在单个 chip 内堆多层说明

禁止做法：

- 用大面积纯红底直接表达所有错误
- 用 `status-chip` 表达多段详细叙述

### 6.6 按钮 `button.primary` / `button.ghost`

主按钮：

- 红蓝渐变
- 白字
- 用于真正的主动作

幽灵按钮：

- 当前主题的半透明表面
- 边框较轻
- 用于刷新、查看、非破坏性操作

使用规则：

- 一个视区内只保留一个主按钮焦点
- `refresh-action` 是已有高优先级刷新按钮变体，后续刷新按钮优先复用其结构

禁止做法：

- 同一组操作里出现多个视觉同权的主按钮
- 把危险操作伪装成普通 ghost

### 6.7 表单域 `field`

当前特征：

- label 与输入分层
- 输入底使用 `--panel-solid` 或等价主题表面
- `14px` 圆角输入框
- 文本区最小高度较高，适合 Prompt 输入

使用规则：

- 字段标签统一使用 muted
- 双列表单默认使用 `.form-grid`
- 宽字段使用 `.field-span-2`

禁止做法：

- 让 placeholder 替代 label
- 在同一主题中混用不一致的输入表面

### 6.8 表格与数据密集区

当前特征：

- 表头使用比正文表面更明确的层级底色
- 表头文字 muted
- 行 hover 使用浅蓝透明高亮
- 宽表通过各自滚动容器承载

使用规则：

- 宽表必须放入独立 scroll 容器，不得撑破页面主布局
- 主数据使用 `var(--ink)`，辅助字段使用 `var(--muted)`

禁止做法：

- 让整个页面横向滚动来适配单张表
- 在表格里混入过多彩色文本造成噪声

### 6.9 告警与提示 `inline-warning`

当前特征：

- 橙色透明底
- 橙色边框
- 小号说明文，行高较大

使用规则：

- 用于可继续操作但需注意的提示
- 严重错误仍应通过更明确的错误卡或状态区域表达

### 6.10 代码块 / 详情块

当前特征：

- 使用与当前主题有明确对比的实体底
- 代码文字保持蓝色系并满足可读性
- 独立边框

使用规则：

- 表达公式、表达式、路径、片段日志、结构化 JSON 时统一复用

禁止做法：

- 在代码块中混用正文排版
- 用亮色底承载长代码段

### 6.11 Badge / Pill / Empty State

规则：

- badge/pill 用于局部标签、轻量状态、筛选状态
- empty state 保持当前主题的弱提示表面，不抢主视图
- 不为每个模块单独重造空状态插画风格

## 7. 强调与状态表达规则

### 7.1 强调优先级

优先顺序：

1. 标题层级
2. 数值亮度
3. 卡片位置
4. 胶囊态容器
5. 语义颜色

### 7.2 颜色使用边界

- 蓝色：交互激活、选中、工作区切换、主信息增强
- 红色：品牌热区、风险能量、模块视觉对冲
- 绿色：在线、通过、成功
- 橙色：警示、待确认
- 红色语义危险：只用于不可逆或明显失败

### 7.3 模块差异允许范围

允许变化：

- Hero 局部渐变分布
- accent card 的红/蓝权重
- 数据卡局部装饰层

不允许变化：

- 改掉主背景结构
- 改掉标题字体
- 改掉标准圆角
- 改掉 ghost / surface / workspace pill 的主语法

## 8. 响应式规范

当前样式断点族应作为后续页面默认标准：

| 断点 | 角色 | 主要策略 |
| --- | --- | --- |
| `1380px` | 大桌面收缩 | 多列摘要和密集看板从 4 列降到 2 列 |
| `1120px` | 平板/窄桌面 | `shell` 由双栏改单栏，侧栏收成折叠菜单，多数组件改 1 列 |
| `760px` | 手机主断点 | `main` padding 收紧，Hero 纵向堆叠，workspace pills 横向滚动，surface padding 降到 `14px` |
| `520px` | 超窄手机 | 单列 KPI、进一步压缩细分网格 |

响应式规则：

- 桌面优先保持信息密度；移动端优先保持操作可达和阅读连续性。
- 窄屏下允许胶囊导航、状态条、候选标签横向滚动。
- 宽表与超宽数据块必须在模块内部滚动，不得破坏全局 viewport。

## 9. 工程映射

后续开发优先复用现有类与 token，不要重新命名一套相同职责的样式。

| 设计语义 | 当前工程锚点 | 说明 |
| --- | --- | --- |
| 页面背景 | `body`, `--bg`, `--rail`, `[data-theme]` | 深色默认/浅色可选 + 红蓝径向光斑 |
| 平台骨架 | `.shell`, `.rail`, `.main` | 侧栏 + 主内容区 |
| 品牌区 | `.brand`, `.brand h1`, `.brand-mark` | 平台 logo 与品牌标题 |

工程要求：

- 如新增页面需要同类组件，优先扩展已有类或抽离共用 token，不要复制一份近似样式。
- 若确需新类名，命名必须表达语义职责，而不是页面临时位置。

## 10. 现状兼容 vs 新页面推荐

### 10.1 现状兼容

以下实现可保留，但不建议作为新页面默认基线：

- 通用 `.hero h2` 的 `36px` 大标题
- 少数历史浅色卡片或浅色渐变块
- 个别模块的局部密集布局特化

### 10.2 新页面推荐

新页面优先遵循：

- 模块级 Hero 标题约 `28px`
- 复用同一套主题感知玻璃卡，不新增独立且不互通的卡片体系
- 子导航优先复用 `.workspace-tab`
- 刷新/查看类操作优先复用 `button.ghost`
- 复杂模块的默认第一屏结构为：Hero -> 状态摘要 -> workspace pills -> 主工作卡

## 11. 文档使用方式

新建页面或新模块时，建议按以下顺序执行：

1. 先从本文档选择页面骨架和组件组合
2. 再从 [styles.css](styles.css) 复用 token 与现有类
3. 只在无法覆盖时新增模块级变体
4. 在 live GUI 的深色与浅色主题中分别检查颜色、标题层级、圆角、状态表达是否一致

## 12. 验收清单

页面设计或实现完成后，至少核对以下项：

- 深色与浅色主题是否都保持红蓝双强调、玻璃卡片语言和一致的信息层级
- 一级标题、二级标题、标签眉题、正文、代码块是否落在本文档层级内
- 是否复用了现有 token，而不是临时新增一套颜色和圆角
- 是否复用了 `surface`、`workspace-tab`、`status-chip`、`field`、`ghost/primary button` 等标准组件语法
- 桌面、平板、手机三类场景下布局是否按 `1380 / 1120 / 760 / 520` 断点收敛
- 宽表和数据密集区是否采用局部滚动，而不是破坏全局布局
- 模块差异是否只落在强调层，而不是改变整个平台基座
- 主题切换是否保持刷新、筛选、任务启动和业务状态完全不变
- 键盘焦点、文本对比度和减少动画偏好是否在两套主题中可用

达到以上条件，才可视为符合 FXAlpha GUI 设计标准。
